# Market conventions

General guidance from common practice, not law and not a complete list. Confirm each item with the user before it
reaches a CV. "Common" means many employers in that market expect it; "uncommon" means most do not. The user decides.

## How the rows are used

- `market.conventions` in profile.md takes the photo, age, marital status and references line answers. A value
  of `true` means the user chose to include that item; the convention table only suggests the default.
- `market.cv_page_limit` is the page limit the writer and the rendering checks use. Use the upper figure of the row
  unless the user wants the shorter CV.
- The date format and paper size feed the CV template. Paper size follows the market, not the posting language.
- Salary in the CV is a choice. The default is to leave it out; the salary floor is kept in profile.md and is never
  printed unless the user asks.
- Age and marital status are personal. They appear only when the user chooses to show them, and never for an
  employer that did not ask.

## Notes per market

- **US and CA:** photos and personal details are left out; one page is common for early careers.
- **GB and AU:** two pages are typical; references are not listed, with the "available on request" line.
- **DE:** a photo and date of birth are common in many CVs; a user who omits them should say so in the cover letter only
  if asked. Use the full date format.
- **FR and ES:** a photo is common; date of birth is common in some sectors; a cover letter is expected.
- **NL and SE:** the photo is common in some sectors; references are optional or on request.
- **MX, BR, PE, IN:** personal fields such as date of birth and marital status are common in CVs here; the user
  decides, and the page limit is often two.

Every row is general guidance. A posting that states its own rule overrides the row for that opening, and the user
confirms the choice.
